# Smart Shell / Smart Files

A production-grade file manager + app shell written in **pure Rust** on **egui/eframe**.
One code base ships as:

| Target | How | Real filesystem? |
|---|---|---|
| Linux native (X11 **and** Wayland — Gnome, Wayfire, KDE…) | `cargo run -p smart-ui-egui --release` | ✅ yes — your drives, your files |
| **AppImage** (portable, double-click) | `scripts/build-appimage.sh` | ✅ yes |
| WebAssembly (this sandbox preview) | `xtask bundle` → single `index.html` | demo VFS (browsers cannot touch your disk) |
| Windows / macOS / FreeBSD | same `cargo run` (see notes below) | ✅ yes |

There is **no hand-written JavaScript or TypeScript** in this project. The only script
in the web page is the wasm-bindgen bootstrap, which `xtask bundle` generates.

## Why egui (and not iced or gpui)

You asked for a verdict, so here it is:

- **gpui** has no WebAssembly target and its Linux story is immature. It fails the
  "linux + wasm + windows + macos + freebsd from one code base" requirement outright.
- **iced** is efficient, but its widget set makes a Finder-class file manager
  (tables with sortable columns, tree sidebar, context menus, command palette,
  multi-window chrome, drag & drop between panes) a large amount of custom work, and
  its web support trails egui's.
- **egui/eframe** is the only crate that gives you *all* of: identical rendering on
  X11, Wayland, Windows, macOS and in the browser; event-driven repaints (idle CPU ≈ 0 —
  the "egui is wasteful" claim only applies to apps that call `request_repaint()` in a
  loop; this one does not); and a mature immediate-mode widget set that this code base
  already uses heavily.

The "wasteful" reputation comes from immediate mode re-tessellating every frame *while
you interact*. At rest this app repaints nothing. Efficiency-critical paths (search,
thumbnailing, copy jobs) run off-thread in `smart-core` via rayon and never block the UI.

## Repository layout

```
smart-files/
  crates/smart-core      backend, zero UI code:
                           vfs (local · memory · phone), search (nucleo), job queue
                           (copy/move/trash with progress), zip archives (+password),
                           devices (lsblk + sysinfo, real mount/unmount), app launching
                           (xdg-open / open / cmd), audio, thumbnailer
  crates/smart-ui-egui   the shell: design tokens, depth primitives, chrome
                           (sidebar/toolbar/tabs/status bar), content grid + list,
                           modals, command palette, search sheet, terminal, photos
  crates/xtask           JS-free build tooling: icon rasteriser (Solar set via resvg),
                           demo-audio synth, wallpaper generator, single-file bundler
  assets/                generated by `xtask assets` (icons, fonts, audio, wallpapers)
  tools/                 appimagetool (for scripts/build-appimage.sh)
scripts/
  build-appimage.sh      native build → portable .AppImage
```

The design system lives in `smart-files/assets/tokens.toml` ("Smart Design v0.1"):
light *and* dark themes, accent `#2f6feb` / `#6f9bff`, Inter type ramp, 4.5:1 contrast
contract. The UI reads these values verbatim.

## Build it yourself

Prereqs (Debian/Ubuntu):

```sh
sudo apt-get install -y build-essential pkg-config fonts-inter \
  libxkbcommon-dev libwayland-dev libx11-dev libxrandr-dev libxi-dev \
  libxcursor-dev libgl1-mesa-dev libegl1-mesa-dev
curl https://sh.rustup.rs -sSf | sh -s -- -y -t wasm32-unknown-unknown
```

### Native (Linux — works on Wayfire *and* Gnome/X11)

```sh
cd smart-files
cargo run -p smart-ui-egui --release            # real filesystem
cargo run -p smart-ui-egui --release -- --demo  # seeded in-memory world
```

winit auto-selects Wayland when `WAYLAND_DISPLAY` is set and falls back to X11
(`DISPLAY`) otherwise — so the same binary runs unmodified under Wayfire and Gnome X11.

### AppImage

```sh
scripts/build-appimage.sh
# → smart-files/Smart-Files-x86_64.AppImage   (runs on any glibc Linux)
```

### WebAssembly (what this sandbox serves)

```sh
cd smart-files
npm i @iconify-json/solar --prefix /tmp/ic            # icon source for xtask
SOLAR_JSON=/tmp/ic/node_modules/@iconify-json/solar/icons.json \
  cargo run -p xtask -- assets                        # once: icons/fonts/audio/wallpapers
cargo build -p smart-ui-egui --lib --target wasm32-unknown-unknown --profile wasm
cargo run -p xtask -- bundle                          # → self-contained index.html
```

`xtask bundle` base64-embeds the wasm so the page is one file with no network fetches.

### Windows / macOS / FreeBSD

Same `cargo run -p smart-ui-egui --release`. Notes:
- Windows: no extra deps; app launch uses `cmd /c start`, trash uses the `trash` crate.
- macOS: needs a `cargo` toolchain; launch uses `open`. (Code-signing/notarisation for
  distribution is the only extra step — out of scope for this pass.)
- FreeBSD: winit + glow build on FreeBSD/X11; drop the `wayland` feature in
  `crates/smart-ui-egui/Cargo.toml` if your winit version complains.
This pass is 100% validated on Linux; the other targets compile from the same source
but are flagged for a follow-up validation pass.

## Destructive actions — the UX contract

- **Delete** never removes immediately: it moves to the system Trash (`trash` crate)
  and shows a toast. Permanent delete requires the confirmation modal, which states the
  exact item count and names the first victims.
- Overwrite-on-paste conflicts are confirmed per batch, never silently clobbered.
- Every job (copy/move/trash) is cancellable from the jobs card while in flight.

## Keyboard map (the shortcuts a file manager owes you)

| Key | Action | | Key | Action |
|---|---|---|---|---|
| `Enter` | open / run | | `Ctrl+C / X / V` | copy / cut / paste |
| `Alt+Up` or `Backspace` | up one level | | `Ctrl+Z` | undo last job |
| `Alt+Left` / `Alt+Right` | back / forward | | `Delete` | move to Trash |
| `F2` | rename | | `Shift+Delete` | permanent delete (confirm) |
| `Ctrl+A` | select all | | `Ctrl+K` | command palette |
| `/` | search | | `Ctrl+,` | settings |
| `Ctrl+T` / `Ctrl+W` | new / close tab | | `Space` | quick-look preview |
| `D` | toggle dark/light | | `G` | grid ↔ list |
| `Ctrl+H` | show hidden | | `F5` | refresh |

(The live list is also in the palette and the status bar.)

## Honesty notes

- The **browser preview cannot see your real disk** — that is a browser security
  boundary, not an app limitation. The wasm build therefore boots the seeded demo VFS
  (`smart-core` `demo` feature) so every feature stays exercisable. The native and
  AppImage builds operate on your real filesystem, drives, mounts and apps.
- Mount/unmount shells out to `udisksctl`/`lsblk`; it works where your user has the
  usual polkit permissions and reports a clear error otherwise.
